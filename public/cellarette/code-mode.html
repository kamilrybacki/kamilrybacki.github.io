07 / workflow

Kilka wywołań. Jeden fragment JavaScript.

Napisz async JavaScript workflow z tools.list, tools.search i tools.call. Poznaj wynik, ślad i limity.

Wbudowane code_mode__execute uruchamia treść asynchronicznej funkcji. Zwróć dane przez return.

Włącz narzędzie w profilu

Po zapisaniu odśwież katalog MCP. Flaga jest niezależna od wzorców tools; pozostałe narzędzia nadal podlegają profilowi.

Pierwszy workflow

W narzędziu code_mode__execute przekaż poniższy tekst jako argument code. Wystarczy konfiguracja ze szybkiego startu.

Wynik narzędzia zawiera result oraz calls, czyli nazwy, statusy i czasy wykonanych wywołań. Nie kopiuje argumentów do tego śladu.

Odkrywanie i równoległe wywołania

APIWynik
tools.list()Nazwy i opisy dozwolonych narzędzi.
tools.search(query)Pasujące narzędzia wraz ze schematami.
await tools.call(name, args)Zwykły wynik MCP: content, opcjonalne structuredContent i isError.

Odkrywanie katalogu jest synchroniczne; tools.call jest asynchroniczne. Nie zakładaj, że wynik backendu ma zawsze tekst JSON w pierwszym elemencie content.

Sandbox i limity

ZasóbLimit
Kod wejściowy64 KiB
Pamięć VM / stos16 MiB / 512 KiB
Tura JavaScript / cały workflow1 s / 30 s
Liczba wywołań / równolegle50 / 4
Pojedyncza odpowiedź narzędzia4 MiB
Zwrócona wartość result64 KiB

Świeży runtime QuickJS/WASM nie udostępnia filesystemu, sieci, process, require ani timerów. Nie może wywołać ponownie code_mode__execute.

Zgody, błędy i ponawianie

Każdy krok trafia do wspólnego dispatchera i zachowuje kontrolę profilu, poświadczeń, polityki i zgód. Odpowiedź z isError pozostaje wynikiem narzędzia; sprawdź ją i zwróć agentowi właściwy stan.

Nie ma automatycznego odtwarzania workflow po zgodzie ani błędzie. Wykonane operacje zachowują skutki po timeoutcie, a rozpoczęte wywołanie backendu może jeszcze się zakończyć. Czekaj na wszystkie rozpoczęte wywołania; nie zwracaj wyniku, gdy operacje pozostają w tle.
