Jeden endpoint. Token przypisany do profilu.

Token administracyjny, token profilu i konfiguracja klienta MCP. Utworzenie, rotacja i odwołanie dostępu.

  • Utwórz token profilu

Klient potrzebuje transportu Streamable HTTP i możliwości wysłania nagłówka Authorization.

Utwórz token profilu

Profil demo musi istnieć. W terminalu z tokenem administratora wykonaj:

Odpowiedź 201 zawiera data.token i data.id. Surowy token jest pokazywany tylko przy wystawieniu. Zachowaj go w mechanizmie sekretów klienta; nie zapisuj go w repozytorium. Pole agent jest etykietą używaną w logach. Wymagany czas życia to liczba sekund do limitu skonfigurowanego przez administratora.

Dodaj połączenie do klienta

To opis wymaganych ustawień, nie uniwersalny plik konfiguracyjny. Nazwy pól i sposób przechowywania sekretów zależą od klienta. Po zapisaniu odśwież połączenie lub katalog narzędzi.

Sprawdź tools/list: dla przykładu startowego zobaczysz demo__version i code_mode__execute. Usługa może udostępniać także wbudowane oczekiwanie na zgodę.

Bearer a parametr profile

Ważny token wiąże żądanie z profilem zapisanym przy tokenie. Nie przełączysz go innym ?profile=. Nieznany, wygasły albo odwołany token daje 401; serwer nie wraca wtedy do wyboru przez query.

Gdy require_profile_token jest wyłączone, wywołanie bez Bearera może korzystać ze starego wyboru ?profile=. Zgody wymagają jednak tożsamości związanej z tokenem profilu — bez niego operacja objęta zgodą zostanie odrzucona.

Rotacja i odwołanie

OperacjaAdmin API
Lista bez surowych sekretówGET /api/v1/profile-tokens
Nowy token w miejsce staregoPOST /api/v1/profile-tokens/:id/rotate
OdwołaniePOST /api/v1/profile-tokens/:id/revoke, JSON {"reason":"manual"} lub {"reason":"compromised"}

Po rotacji zaktualizuj sekret w kliencie i połącz go ponownie. Administracyjne żądania z sesją cookie wymagają nagłówka X-Cellarette-CSRF; dotyczy to także pozostałych mutacji API.
