01 / pierwszy workflow

Od konfiguracji do pierwszego wyniku.

Uruchom lokalną bramkę na Node 22 z jednym narzędziem odczytu. Bez zewnętrznych backendów.

Na tej stronie
  • 1. Przygotuj środowisko
  • 2. Zapisz konfigurację
  • 3. Uruchom aplikację
  • 4. Utwórz token i połącz klienta

Ten przykład wystawia jedno narzędzie: odczyt wersji Node. Nie wymaga serwera MCP upstream, Vaulta ani konta w zewnętrznej usłudze.

1. Przygotuj środowisko

Potrzebujesz Git, Node.js 22 i npm. Node 22 jest wersją używaną w obrazie aplikacji; natywny moduł SQLite musi pasować do wybranego runtime. Poniższe polecenia są dla shella POSIX.

2. Zapisz konfigurację

Zapisz plik jako cellarette.local.yaml. Możesz też pobrać gotowy przykład.

Profil demo widzi tylko demo__version. Domyślny profil wskazuje wzorzec, do którego nie pasuje żadne narzędzie.

Zakres przykładu

consent.enabled: false wyłącza silną zgodę WebAuthn wyłącznie na potrzeby tego lokalnego demo. Przed użyciem operacji wrażliwych skonfiguruj HTTPS oraz rp_id i origin; zobacz silne zgody.

3. Uruchom aplikację

MCP obsługuje POST http://127.0.0.1:8788/mcp. Admin API działa pod http://127.0.0.1:8789. Do dalszych poleceń użyj drugiego terminala z tą samą wartością CELLARETTE_ADMIN_TOKEN.

Przy zdalnym wdrożeniu wystaw MCP i panel przez HTTPS oraz kontrolę dostępu. Przykład ma służyć lokalnym testom.

4. Utwórz token i połącz klienta

Utwórz token profilu demo przez admin API. Następnie dodaj endpoint i nagłówek Bearer do klienta MCP. Przy require_profile_token: true sam parametr ?profile=demo nie wystarczy.

Po połączeniu poproś agenta: „Wywołaj demo__version”. Potem przejdź do pierwszego snippetu Code Mode.
