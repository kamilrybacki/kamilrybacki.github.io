Bring your tools to one endpoint.

Connect MCP, HTTP and CLI backends.

On this page

  • MCP server

Choose a driver for the system you are integrating and add its exposed names to the appropriate profiles.

Choose a driver

DriverUse it for
mcp_proxyConnect an existing MCP server.

cli_passthroughAccept an argument array and apply a policy before running it.

Start from the Quickstart configuration. Merge the shown keys into the existing YAML, keeping other tools and allowlist entries. Restart the gateway after editing it. If the profile already exists, update its tool list in the profile editor. Connect with a token for that profile, then call the named tool in your MCP client. The JSON snippets show the request sent by the client.

Start the local MCP and HTTP demo server

From the repository checkout, after installing dependencies, run this command in a separate terminal. The demo server source binds to 127.0.0.1:9001. Start it before the gateway on the same machine. Stop it with Ctrl+C.

MCP server

The local demo server exposes lookup_product. Splicedock adds the backend name as a prefix, so the client calls catalog__lookup_product.

Use the hostname as seen from the gateway. The configured host and port form an HTTP URL ending in /mcp for Streamable HTTP or /sse for SSE.

HTTP endpoint

Look up a product in the demo API by SKU. The gateway URL-encodes the sku argument and puts it in the path.

Authenticate to an HTTP backend

For a backend that requires a bearer token, replace the tool’s auth block with the following and set CATALOG_API_TOKEN in the gateway environment. Point url at that API, using HTTPS for a remote backend.

Fixed CLI command

Expose node --version as a tool with no arguments. Node.js must be on the gateway’s PATH. If you are using the Quickstart configuration, keep its existing entry for this tool.

Compare the result with node --version in the gateway environment.

CLI passthrough

Expose Git and allow exactly one argument, version. Run command -v git in the gateway environment and use the resulting executable path in both YAML fields.

For a local setup, set a writable binary directory before starting the gateway.

Check that the policy denies another command

The gateway returns a tool error and does not start Git. See policy evaluation order for rule precedence.
